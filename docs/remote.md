# Remote download

Remote download is the only feature that talks to a service, so it is the only feature that
can break without the local engine changing. It lives in its own crate — `wxapkg-remote` —
and the whole transport chain is native Rust: no shared library, no C ABI, no Go runtime.
Removing remote download from a build is a feature flag, not a refactor.

## The stack

| Layer | What it does | Where |
|---|---|---|
| OAuth login (UAL) | QR session on `open.weixin.qq.com`, code → `login_buffer` | `src/oauth.rs` |
| Access API (UAL) | `yybadaccess.3g.qq.com`: profile, keepalive (`check_login` → `refresh_token` → `login_buffer`), MD5 request signing | `src/ual.rs` |
| MMTLS | P-256 ECDH handshake, HKDF-SHA256, AES-GCM 5-byte records against `shortcloud.weixin.com` | `src/ilink/mmtls.rs` |
| iLink envelope | 16-byte packet header, WPKG frame, `EncryptTypeSessionAES` (ciphertext‖nonce‖tag), LZ4 literal blocks | `src/ilink/envelope.rs` |
| Hybrid seal | dual-sealed random key (encrypt type 17), HKDF label `security hdkf expand` (sic — upstream typo, kept verbatim), transcript-hash AAD | `src/ilink/hybrid.rs` |
| Authentication | `ManualAuth` (CGI 3453) and `AutoAuth` over the hybrid seal | `src/ilink/auth.rs` |
| Business CGIs | recent list, attributes, package download — all `WxaRuntimeTransfer` with scene 1029 | `src/wxa.rs` |
| Messages | `proto/*.proto` staged in-tree, generated by `protox` + `prost` at build time (no protoc needed) | `src/pb.rs`, `build.rs` |
| Session / account | the one account in `account.json` (`0600`), pending QR logins, stale marking | `src/session.rs`, `src/store.rs` |
| Metadata cache | names + icons for the recent list, budgeted refresh | `src/meta.rs` |

Wire-level fidelity was proven against the Go reference: with deterministic randomness, the
Rust seal produces a byte-identical envelope, and a live stored session sends a frame the
service accepts (`ret=0`).

## Where state lives

One directory under the platform's application-data root:

| Platform | Path |
|---|---|
| macOS | `~/Library/Application Support/wxapkg-dump/remote/` |
| Linux | `$XDG_DATA_HOME/wxapkg-dump/remote/` (usually `~/.local/share/...`) |
| Windows | `%APPDATA%\wxapkg-dump\remote\` |

```text
account.json         the signed-in account + session credentials, mode 0600
pending/<uuid>.json  logins waiting for a scan, resumable after a restart
metadata.json        Mini Program names / icon URLs, keyed by original id
icons/<sha256>.bin   cached launcher icons
```

Rules the store enforces, because sessions are credentials:

* the directory is `0700`, every file it writes is `0600`;
* writes go to a temporary file and are renamed into place, so a crash cannot truncate state;
* an unreadable `account.json` is moved aside as `account.corrupt-<timestamp>.json` instead
  of being silently replaced;
* credentials never appear in logs or in any API response;
* `WXAPKG_REMOTE_HOME` relocates the whole directory, which is what tests use.

## Using it

```rust
use wxapkg_remote::Remote;

let remote = Remote::open()?;
let session = remote.begin_login()?;                // a confirmed scan replaces the account
let qr = remote.qr_image(&session)?;                // JPEG bytes for the window
let status = remote.poll(&session)?;                // Waiting | Scanned | Authorized | Expired | Cancelled
let account = remote.account()?;                    // Some(..) once signed in
let items = remote.recent(1, 50)?;                  // page 1, 50 per page
let report = remote.download(&options)?;            // packages + optional unpack
remote.delete_account()?;                           // account and caches, gone
```

`poll` is a long poll, so a caller should keep it on a worker and allow ~30 seconds.
Every network call is blocking; shells must call from a blocking thread (CLI directly,
server via `spawn_blocking`, GUI inside `run_job`).

Upstream session expiry (iLink `app_ret -14`, UAL error `40030`) maps to
`Error::SessionExpired`; `Remote::sign_in_again` walks the keepalive chain once before
giving up, so a briefly-stale account recovers without a new scan.

## Builds without it

`wxapkg-remote` is an optional dependency behind the `remote` feature of the GUI (and `remote`
of the server). A build without it:

```bash
cd crates/wxapkg-gui
cargo build --release --no-default-features
```

keeps the window, scanning, export, batch export and settings, and reports remote download
as unavailable with an explanation. The command names are the same either way — the window
code does not branch on the feature.

## Reference

The Go reference lives outside this repository (`应用宝协议/yyb-go`) and is read-only for
this project. The four data messages were ported from its `services/` and `models/wxapp/`
layers; the staged protos in `crates/wxapkg-remote/proto` are the contract. Live-service
tests are `#[ignore]`d:

```bash
cargo test -p wxapkg-remote -- --ignored
```
